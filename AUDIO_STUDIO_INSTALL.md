# UNWIN Audio Studio — install and test (development build)

This branch adds a **local audio-first filmmaking workspace** alongside the existing Director. It is not a finished one-click AI filmmaking suite. **Lip-sync and voice cloning are not installed or integrated**, and model availability depends on your ComfyUI environment.

## Three project modes
1. **Standard Video Director** — existing video workflows.
2. **Dialogue to Video** — enter lines, create an editable shot plan, generate basic Windows SAPI speech, optionally direct with locally running Ollama/Gemma, queue H3 shots and mux finished clips with the master audio.
3. **Audio to Video** — import a recorded soundtrack, optionally transcribe with WhisperX, edit the resulting shots, queue H3 shots and mux.

## Installation (Windows ComfyUI Desktop)
1. **Back up** your working `Unwin-MiniMax-Director` custom-node directory and any unsaved projects. Exit ComfyUI Desktop before replacing files.
2. Download the ZIP for branch `feature/dialogue-audio-director` from GitHub and extract it.
3. Copy the **contents** of the extracted `Unwin-MiniMax-Director` folder into your existing `custom_nodes/Unwin-MiniMax-Director` folder. Do not add an extra nested directory. Do not replace your working `t2v.json` / `i2v.json` with older copies; retain the validated versions with SaveVideo `format.codec`.
4. Restart ComfyUI and check startup logs. Open `http://127.0.0.1:8188/unwin/audio-studio` in your local browser.
5. Create a test project and a two-line dialogue. Try **Create editable shot plan** before generating audio or rendering.

## Required and optional engines
- **Required for core UI:** existing ComfyUI installation, aiohttp (bundled with ComfyUI), Python packages already required by UNWIN Director.
- **Required for mux and audio import:** FFmpeg **and FFprobe** available on PATH or alongside FFmpeg.
- **Offline speech:** Windows PowerShell with System.Speech (Windows SAPI). Basic system voices, not cloned characters or expressive neural TTS.
- **Gemma shot planning (optional):** install and start Ollama locally; pull a compatible model such as `gemma3:4b`. API is `http://127.0.0.1:11434`, no external API.
- **WhisperX (optional):** install `whisperx` in the **same Python environment ComfyUI uses**. The model must be downloaded/cached in advance for offline use. The first uncached model load may attempt a download; offline operation is only assured once cached.
- **MiniMax H3 rendering:** the existing local `t2v.json` and all models and nodes must pass validation. Default shot render is 512×288 and 8 steps; change in code only after VRAM testing.
- **Lip-sync:** not included in this build. You must install and validate a compatible local lip-sync workflow separately. Video output may have unsynchronised mouths until this is added.

## How to test
1. Visit `/unwin/dialogue/engines` and `/unwin/dialogue/capabilities` to see availability.
2. Create a Dialogue to Video project. Enter two lines and create shots. Optionally generate Windows SAPI voices and check the saved project and WAV in ComfyUI output `unwin_director/dialogue/<project-id>`.
3. Optionally use **Direct with local Gemma** if Ollama is running and the model is installed.
4. Queue **one** short shot; monitor the ComfyUI queue. H3 may still fail at runtime due to model/VRAM incompatibility.
5. Once rendered clips exist in the ComfyUI output directory, supply their relative filenames, in order, to **Stitch with master audio**.
6. Inspect audio sync and shot boundaries manually. The mux does not perform lip-sync.

## Safety / limitations
- The interface is **local only**, and the back-end sends render jobs to localhost ComfyUI.
- The master audio is saved with the project and is never regenerated by MiniMax during final mux.
- The timeline is editable but has no waveform editor yet.
- Imported audio transcription has placeholder speaker labels; diarization and speaker voice consistency are not automatic.
- Generated speech uses the default Windows system voice; it does not assign unique voices to different characters.
- No fully automated render-all, character-consistency enforcement, or lip-sync pipeline is claimed.
- The repository branch is a development candidate until it passes live ComfyUI startup, import, render and mux tests.
